# ADR-0013 · 系统凭据的分代写入与清理

状态为 Accepted，2026-11-27。T10 细化 ADR-0005 的跨存储恢复策略。

**背景。** SQLite 与系统凭据库各自提交操作。原地覆盖密码会立即影响共享条目的其他资源，也无法在随后的 SQLite 提交失败时找回旧值。

**决定。** 每次设置、轮换或重新录入都生成独立的目标级引用。应用先将候选引用写入 SQLite 清理队列，再将用户名和密码作为一个条目写入当前用户的 macOS Keychain 或 Windows Credential Manager。随后在一个短事务中重新核验工作区、目标、已确认端点和原引用，并发布新引用。等待终端输入或系统授权时不持有 SQLite 写事务。凭据管理进程共用目录级文件锁；进程退出会释放锁。

**恢复与共享。** 候选条目在发布前始终可回收，失败的轮换保留原引用。解除旧引用会触发持久清理记录；清理前查询全库引用数，仍被引用的条目继续保留。已提交但系统删除失败时，命令报告清理待办和脱敏原因，后续成功变更或本地 `credential cleanup` 可重试。显式重绑只在同一绑定、同一目标和相同已确认主机、端口、TLS、类型的资源之间进行，提交时再次检查源与目的。移除资源将其停用并解除引用，保留原有审计关系。

**安全与代价。** 系统条目名限于应用命名空间、目标 UUID 与随机 UUID，命名空间由该私有 catalogue 的规范目录派生。备份恢复到新目录后，即使引用相同，也无法删除源目录的系统条目；用户在新目录重新录入或重绑。旧版不透明引用保留为可修复状态，清理程序只操作本应用识别的条目。已经从系统存储删除的秘密不能从 SQLite 备份恢复。系统用户权限和系统凭据库自身的访问策略仍决定宿主边界。

**接口。** 本机终端在提示前关闭回显，Rust 管理入口只返回状态和诊断。受信 Rust 连接器在回调内使用账号密码，系统读取前和交给连接器前分别复核 T09 授权。构建 crate 的依赖图不包含原生 provider。MCP 和 WebView 没有读取凭据内容的命令。

**验证。** T10-A01–A03 覆盖两种原生凭据库、故障注入、并发、共享条目、恢复副本隔离及假秘密扫描。[T10 任务卡](../../plan/tasks/T10-native-credentials.md)

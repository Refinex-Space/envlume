# ADR-0012 · 端点确认与绑定级远端授权

状态为 Accepted，2026-11-27，T09。

**背景**　同一项目的多个工作区可共享目标和资源定义。DEV 和 TEST 可以各有名为 `primary-db` 的不同资源。旧版 SQLite 保存了连接参数与 grant，未记录端点的本地确认。

**备选方案**　按资源别名授权会混淆不同目标；升级时自动认可现有端点无法证明用户确认过当前地址。用一个全局环境选择器决定远端路由还会影响同一会话中的并发调用。

**决定**　使用已验证的 binding 确定项目，每次远端操作显式解析 target 与 resource 别名，再检查其 UUID、状态、kind、risk、端点确认、能力和授权时效。授权签发、目录投影及请求分发共享 v0.1 矩阵。provider 或 connector 使用请求内的 `AuthorizedResource::binding()` 时再核对 grant 身份及端点快照；排队期间的撤权、过期或重授均会使旧请求失效。PROD 的独立只读审批及表/列脱敏尚未同时具备，当前一律拒绝远端操作。日常配置支持改名、提高风险和收紧分类。仓库提示、能力标签和单次调用参数均不能扩大矩阵。

**安全影响**　本地确认展示项目、绑定、目标、资源及连接参数，在 SQLite 短事务中重查用户所见的状态。主机、端口、数据库、TLS 或所属目标发生变化时，撤销该资源在所有绑定上的 grant，同时解除旧凭据引用。风险或分类变化撤销目标关联的远端 grant。桌面 main 窗口新增只读 `list_environments`；绑定由 Rust 启动上下文指定并核验当前目录。IPC 和 MCP 都只返回受权别名与健康摘要，管理命令只在本地终端接受确认。

**迁移与风险**　迁移 006 保留资源元数据、凭据引用和授权历史，撤销旧版远端 grant；管理员需重新确认端点并签发 grant。解除引用不删除系统凭据。用户仍须辨认并批准正确的端点，DNS、TLS 和实际 MySQL 会话的校验由 T11 完成。

**验证证据**　T09-A01–A03 逐项核对策略矩阵、取密钥与建连计数、SQLite 事务和三个入口的下一次调用。[T09 任务卡](../../plan/tasks/T09-target-resource-policy.md)

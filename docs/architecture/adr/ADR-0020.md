# ADR-0020 · Codex 可信项目接入与验证证据

状态为 Accepted，2026-11-28，T17。

**配置所有权。** 安装目标为已登记工作区下的 `.codex/config.toml`。沿用 ADR-0018 的终端确认、严格 command/args 所有权、私有备份、原子发布及补偿。默认或选定的 Codex 用户配置目录落在工作区内时，预览即报告 SCOPE_CONFLICT。项目未获信任时，由用户在 Codex 中复核项目。Envlume 的本地登记和 Codex 的信任选择分别由各自管理。

**配置生效证明。** 从绑定根启动已安装的原生 `codex app-server`，经 STDIO 读取 `config/read`。核对项目层的实际目录、启用状态、原始管理条目、最终生效的 STDIO 命令及各参数的来源。用户层同名服务即使具有相同命令和绑定参数，也不能为未加载的项目层提供证明。配置响应仅在进程内解析，读取总量有界。返回给用户的信息限于 Envlume 条目和诊断。[Codex 项目配置](https://developers.openai.com/codex/config-basic) · [App Server](https://developers.openai.com/codex/app-server)

**生命周期。** `install` 和 `verify` 分别核对稳定网关的实际 `project_context` 及 Codex 当前配置。成功返回 CONFIGURED、gatewayVerified 和 clientConfigVerified。clientVerified 保留给客户端连接证明。配置检查不启动项目线程、其他 MCP 或模型轮次。首次安装失败按 T15 回滚；现有登记验证失败标为 STALE。撤销 Envlume 绑定后，已连接的 Codex 仍须对下一次调用重新授权。

**真实客户端验收。** 独立测试用户配置和临时项目中，启动真实 Codex 临时线程；用 `mcpServerStatus/list` 发现服务后执行 `mcpServer/tool/call`。对照客户端协商日志和本地 requestId 审计记录。测试中使用合成配置，只有测试程序设置该临时项目的信任。[T17 验收](../../plan/tasks/T17-codex-integration.md)

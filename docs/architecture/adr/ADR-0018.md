# ADR-0018 · 项目配置的所有权、事务恢复与验证状态

状态为 Accepted，2026-11-27，T15。

**背景与选择。** 客户端配置可含第三方服务、凭据、未知字段和用户注释。整文件覆盖会丢失这些内容。仅按服务名删除还会误删用户创建的同名服务。三个适配器共用绑定校验、变更预览和事务流程，各客户端后续负责其实际加载与重载证明。

**所有权。** 唯一登记键为 binding 与客户端。配置位置来自已登记目录及固定的项目相对路径。安装只管理 JSON 的 `mcpServers.envlume` 或 TOML 的 `mcp_servers.envlume`。将管理条目解析为严格的 command/args 描述，再计算 SHA-256；字段增删、命令或参数变化均使所有权检查失败。登记表同时保存原文件及预期发布文件的整文件字节摘要，缺失文件单独表示。旧登记若缺少所有权证据，需人工核对。

**事务。** 确认前展示客户端、项目作用域、位置、管理键及拟写入的启动描述。确认后重新校验目录身份、登记、原文件和稳定 CLI。先在用户私有备份目录保存原始字节并持久化 SQLite 意图，再通过固定目录句柄在目标目录暂存和发布。Envlume 写入者共享进程锁，配置发布与绑定撤销通过短 SQLite 事务排序；交互和 MCP 验证均在该事务外执行。

**并发和恢复。** 新文件采用禁止覆盖的改名。替换既有文件时，macOS 交换两个目录项，Windows 使用保留被替换文件的 ReplaceFileW。发布后核对被置换内容，遇竞争保留外部版本。卸载或补偿时，若整文件仍与发布摘要一致，精确还原原字节或原先缺失的状态；若用户只修改了其他内容，则只移除仍属该登记的条目。管理条目已改、配置不可解析、目录身份失效或发生二次竞争时保留文件并报告原因。确认恢复可重放未完成事务并清理相应暂存文件；遇未知的被置换内容需人工核对。独立编辑器不参与 Envlume 进程锁。[Windows 替换及部分失败语义](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)

**凭据与权限。** 配置备份可能含用户已有的第三方凭据，原文保存在 Envlume 私有 backups 目录。SQLite 只保存位置、摘要、操作阶段和验证状态。修改已有文件时保留其访问权限。备份按本地用户访问权限保护，仍须按含秘密文件管理。CLI 和桌面原生宿主共用同一入口，WebView 权限沿用现有清单。

**兼容与交接。** 迁移 010 扩展 `client_integrations`。公共探针从绑定目录启动已校验的稳定 CLI，通过 STDIO 调用 `project_context` 并对照项目及绑定别名。CONFIGURED 表示配置已写且网关核对成功，CONNECTED 要求客户端适配器另外提供加载证明。T16–T18 在本事务上分别接入真实客户端。[验收命令与证据](../../plan/tasks/T15-integration-lifecycle.md)

# ADR-0014 · MySQL 拨号地址、元数据范围与连接池隔离

状态为 Accepted，2026-11-27，T11。

**背景。** T09 的主机名确认与 T10 的凭据引用并不能证明下一次 DNS 应答属于获准端点。先检查地址、再让驱动重新解析主机，会在校验与实际拨号之间留下空隙。数据库账号自身能看到的对象也可能多于当前绑定需要的对象。

**决定。** 采用锁定的 `mysql_async 0.37.1`，使用 `resolved_ips` 把已核验地址直接交给驱动，同时用本地配置中的原始主机名做 TLS 身份验证。关闭自动改用本地 socket 的路径。平台 TLS 使用系统信任根，若配置专用 CA 则仅信任该 CA。选择该驱动是因为此版本有公开的固定地址接口；所检查的 SQLx MySQL 0.9.0 选项未提供等价接口。[驱动选项](https://docs.rs/mysql_async/0.37.1/mysql_async/struct.OptsBuilder.html)

**本地策略。** 操作者确认资源的拨号 IP、可选 CA 和元数据清单。所有 DNS 应答必须落入该资源批准的 IP 集合；未指定路由、未指定地址、组播、链路本地等地址均拒绝。`DISABLED` 只可用于显式回环地址。连接参数不出现在 MCP 参数中。连接、元数据分别要求有效的 `resource.connect`、`database.schema` grant。可返回的表、列和索引名称由用户列举；复合索引还要求其全部列可见，表达式索引不返回。

**迁移。** SQLite 迁移 008 给旧资源添加空路由和空清单。用户首次配置或更改 IP/CA 时撤销远端 grant、解除旧凭据引用。只改变对象清单时保留凭据并撤销 grant；更改主机、端口、数据库、TLS 或所属目标时清除旧路由与清单。共享凭据的重绑定必须具有相同的目标及服务器信任配置。新的授权编号代表新的批准。

**资源与失败。** 池键包含 binding、target、resource 和 grant UUID，并比较资源快照与实际拨号地址。访问前重新授权，取连接后、元数据操作之间及返回前再次核对。撤权后原池无法服务下一次请求；授权变化在下次本地刷新时发起回收，无访问时由空闲清理回收。驱动的账号信息只在连接器进程内使用。诊断返回固定类别和处理指引，审计记录获准资源的 UUID 与摘要。

**验证。** 两个 MySQL 只读账号分别校验数据库、表列索引、TLS 与重授权，连接复用及回收与服务器会话视图核对。[T11 任务卡](../../plan/tasks/T11-mysql-connect-schema.md)

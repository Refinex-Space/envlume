## 交付目标

用安装后的产品串起桌面、CLI、Agent 和真实测试资源，形成可供发布评审复核的一组证据。

## 实施与产出

1. 使用 T21 候选包，从首次启动、真实 Java 8/Spring Boot 导入、JDK/Maven 诊断开始，配置 DEV MySQL 并授权，再由 Agent 查表、执行 Maven、取回证据。覆盖三个真实客户端各一次 POC，记录各自版本、OS、协议和调用结果。
2. 运行 SEC-001 至 SEC-012。用假秘密标记扫描 UI、MCP、CLI stderr、SQLite/WAL、备份、构建子进程、日志及导出。核对所有受控动作有 requestId，执行有 evidenceId，查询结果未整批持久化。
3. 测量冷启动首次可交互（目标 ≤3 秒）、已有工具的基本诊断（通常 ≤5 秒）、数据库默认 5 秒/200 行/256 KiB。记录硬件、冷/热条件、样本和实测值。远程超时与本机探测分开计时。
4. 压测有界 MCP 并发、连接池、SQLite 多进程读写/锁争用/崩溃恢复，以及连接断开、任务取消/超时后的进程与句柄。复测断网、凭据损坏修复、配置还原、数据升级。

## 验收

- **T22-A01**　每个实际客户端均可验证项目绑定。关闭桌面后至少走通 schema → task_run → 本地证据复核。比较真实 Maven 报告、schema 标记与 evidenceId，记录步骤及输出。
- **T22-A02**　十二项安全负例全部通过，权限外访问无底层副作用，假秘密扫描命中为零。为每个功能验收编号关联证据或原生验收责任卡。
- **T22-A03**　预算清单包含目标、实测与差异。越界记录复现方式和处置，硬性安全上限超标阻塞发布。证据与候选包可互相定位。

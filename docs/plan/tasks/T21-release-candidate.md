## 交付目标

生成同一修订的两个 macOS DMG、一个 Windows NSIS 安装包及匹配的独立 CLI，供原生验收。

## 实施与产出

1. 建立可复现的 release 构建，固定桌面/CLI/schema 兼容范围，标注架构、版本和 SHA-256。接通可选或手动更新检测，断网可继续使用。升级前备份，迁移失败回滚或进入只读恢复。
2. 对 macOS 公共发行执行 Developer ID 签名、公证及产物校验。按架构 §16、§19 核对 Windows 签名及公发条件，检测 WebView2 缺失并给出可解释的处置。签名材料由发布环境注入。
3. 准备安装、卸载、重装、恢复和首用文档、README、SECURITY、安全限制、变更说明与许可证清单。对照仓库 MIT 和依赖许可制备随包声明，许可证变更另行决策。
4. 准备 GitHub Releases 所需制品清单。生成可在干净用户环境使用的前一兼容版本或基线安装夹具，明确实际覆盖的升级起点。

## 验收

- **T21-A01**　三个安装包及独立 CLI 均可按清单验证哈希、架构、版本、签名/公证适用状态，版本匹配失败给出诊断。缺公发材料明确标记阻塞。
- **T21-A02**　同一修订通过 Rust/前端构建、测试、审计、依赖许可、锁文件和秘密扫描。离线启动可导入项目、读配置及探测工具。
- **T21-A03**　演练迁移成功、迁移中止、恢复备份和手动更新不可用，原资源映射、绑定、凭据引用可恢复。Windows 运行中的 CLI 有可恢复的替换路径。

## 交接

移交候选版本、源修订、制品 SHA-256 和签名检查记录。后续修复重出受影响的候选包并重验。

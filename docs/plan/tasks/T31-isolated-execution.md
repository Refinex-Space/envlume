## 交付目标

只有在具体威胁模型和平台机制已确认时，才提供带明确保证范围的隔离执行。

## 实施与产出

1. 通过 ADR 定义目标项目、文件/网络/进程权限、macOS 和 Windows 的可用机制、性能及失败模式。明确隔离模式与原生可信工作区模式的适用范围。
2. 复用具名任务、凭据剥离、证据和取消生命周期。配置的隔离级别不可用时给出明确诊断，保持受限任务拒绝，保留已有项目的兼容行为。

## 验收

- **T31-A01**　在声明支持的原生平台运行受控构建，验证允许的输入输出、资源限制和取消/回收。用负面用例确认文件、网络、进程边界及凭据不可见。
- **T31-A02**　回归本机模式与升级前任务，证据清楚标明实际隔离模式和限制。未被原生测试覆盖的平台不得声明支持。

## 交接

移交 ADR、平台保证矩阵和真实项目执行记录，或记录需求未选入的决定。
